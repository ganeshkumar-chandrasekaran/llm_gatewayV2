Quick Start (Zero Config)

The gateway ships with a mock provider that works out of the box — no API keys needed. Just select mock from the provider dropdown, check Agent + MCP Tools, and send a prompt.

The mock provider intelligently matches your prompt to the right MCP tool based on keywords like add, multiply, divide, sqrt, time, etc.

Two Modes of Operation

Chat mode (Agent unchecked) — sends your prompt to /v1/chat. The LLM responds directly with text. No tools are used.

Agent mode (Agent checked) — sends your prompt to /v1/agent. The gateway spawns an MCP server, discovers tools, and runs an agentic loop:

User Prompt → LLM decides which tool to call
→ MCP Server executes the tool
→ Result sent back to LLM
→ LLM formats the final answer

Using with cURL

# Agent mode (with MCP tools)
curl -X POST http://localhost:8100/v1/agent \
  -H "Content-Type: application/json" \
  -d '{"prompt": "multiply 4 times 2", "provider": "mock"}'

# Chat mode (plain LLM)
curl -X POST http://localhost:8100/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Say hello", "provider": "mock"}'

Connect a Real LLM Provider

To use a real LLM instead of mock, create a .env file in the parent directory (one level above llm_gatewayV2/). Copy from .env.example and fill in your key:

# For Google Gemini (free tier available):
# 1. Go to aistudio.google.com → Get API Key
# 2. Add to your .env file:
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-2.5-flash

# For GitHub Models (free tier available):
# 1. Go to github.com/marketplace/models
# 2. Pick a model → click "Use this model"
# 3. Create a Personal Access Token at github.com/settings/tokens
# 4. Add to your .env file:
GITHUB_ACCESS_TOKEN=your_pat_here
GITHUB_MODEL=openai/gpt-4.1-mini

Restart the gateway after updating .env. The new provider will appear in the dashboard automatically.
